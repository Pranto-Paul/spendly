❯ explain the project structure to me                                           

  Thought for 23s (ctrl+o to expand)

⏺ This is a typical structure for a small to medium-sized Flask application. It
  separates the concerns (logic, data, presentation) into distinct directories,
  which is good practice for maintainability.

  Here is a breakdown of the project structure:

  📂 Root Directory (expense-tracker/)

  This is the main container and holds the core files that orchestrate the
  application:

  - app.py:
    - Purpose: This is the entry point of the entire application. It initializes
      the Flask app instance.
    - Function: It defines all the routes (e.g., /, /login, /expenses/add). When
      a user navigates to one of these URLs, the corresponding function in this
      file is executed. This function is responsible for deciding what data to
      fetch and which template to render.
  - requirements.txt:
    - Purpose: A manifest file that lists all the external Python libraries
      (like flask, werkzeug, pytest, etc.) the project needs to run. This allows
      anyone to quickly recreate the correct environment using pip install -r 
      requirements.txt.
  - database/ (Directory):
    - Purpose: This directory is intended to house all the data access layer
      code. It completely separates the how we store data from the how we
      display it.
    - Files:
      - __init__.py: Standard Python file that marks the directory as a package.
      - db.py: (Current Focus/TODO) This file is where we will implement the
        connection to the database (e.g., SQLite), functions to create tables,
        and functions to insert or retrieve data.
  - static/ (Directory):
    - Purpose: This is where all static assets—files that don't change based on
      application data—are stored.
    - Files:
      - css/style.css: Holds all the styling for the application.
      - js/main.js: Holds any client-side JavaScript logic.
  - templates/ (Directory):
    - Purpose: This directory holds all the HTML files. Flask uses the Jinja2
      templating engine, which reads these files, injects dynamic Python data,
      and serves the final HTML page to the user.
    - Files:
      - base.html: The main layout template (the header, footer, and wrapper).
        All other pages generally extend from this template.
      - landing.html: The home page view.
      - login.html: The user login page.
      - register.html: The user registration page.

  ⚙️ Workflow Summary (How it works)

  1. Request comes in: A user requests a page (e.g., /login).
  2. app.py handles it: The app.py file sees the request and executes the
     login() function.
  3. Business Logic (future): The function might check a database using a
     function from database/db.py.
  4. Render: The function uses render_template("login.html"), passing any
     necessary data.
  5. Client View: Flask serves the HTML from templates/login.html, which in turn
     refers to styles from static/css/style.css.

  ---

  In essence, we are building the skeleton, and the next logical step is to give
  the skeleton a brain and a memory (i.e., complete the database setup).
